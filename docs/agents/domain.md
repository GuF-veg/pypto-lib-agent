# Domain docs

This repo uses a single-context layout: `GLOSSARY.md` at the repo root and
architecture decision records (ADRs) in `docs/adr/`.

## Before exploring the codebase

Read the root `GLOSSARY.md` and ADRs relevant to the area being explored.
If these files do not exist, proceed silently. The domain-modeling skill
creates them when terms or decisions are resolved.

## Use the glossary's vocabulary

Use defined terms in issue titles, proposals, hypotheses, and test names.
If a needed concept is absent, reconsider whether it belongs to the project's
domain or note the gap for domain modeling.

## Flag ADR conflicts

If a proposal contradicts an existing ADR, identify that ADR and explain why
the decision should be reconsidered before overriding it.
